# Контракт API для фронтенда

> Актуально на 2026-07-27. Источник правды по эндпоинтам и схемам —
> **Swagger UI** запущенного бэкенда: `http://localhost:8080/swagger-ui/index.html`
> (сырая спека — `/v3/api-docs`). Этот документ описывает то, чего в Swagger нет:
> соглашения, формат ошибок и планируемые изменения контракта.

## Базовое

* Base URL локально — `http://localhost:8080`. Все пути начинаются с `/api`.
* Все тела запросов и ответов — JSON, имена полей — **camelCase**.
* Тестовые логины и пароли — в [backend/README.md](../backend/README.md),
  раздел «Тестовые данные».

## Аутентификация

1. `POST /api/users/auth/login` с телом `{"username": "...", "password": "..."}`.
2. В ответе — `{"accessToken": "<JWT>"}`. Токен живёт 24 часа.
3. Токен передаётся в каждом запросе к закрытым эндпоинтам заголовком
   `Authorization: Bearer <JWT>`.
4. Ответ **401** от любого эндпоинта означает «токен отсутствует, протух или
   невалиден»: токен стереть, пользователя отправить на страницу логина.

Refresh-токена пока нет — после истечения суток пользователь логинится заново.
Cookie не используются, поэтому CORS-режим `credentials` фронту не нужен.

## Формат ошибок

Любая ошибка — [RFC 9457 Problem Details](https://www.rfc-editor.org/rfc/rfc9457),
`Content-Type: application/problem+json`:

```json
{
  "type": "about:blank",
  "title": "Unauthorized",
  "status": 401,
  "detail": "Требуется аутентификация.",
  "instance": "/api/users/profile",
  "timestamp": "2026-07-26T10:00:00Z"
}
```

Нюанс: поле `instance` заполняется в ошибках, прошедших через обработчик приложения;
в 401, которые отдаёт JWT-фильтр (нет токена / битый токен), его пока нет —
на `instance` не завязываться (унификация — тикет T-14).

Ошибка валидации формы дополнительно несёт словарь `errors`
(имя поля → список сообщений, пригодных для показа пользователю):

```json
{
  "title": "Ошибка валидации",
  "status": 400,
  "detail": "Ошибка валидации.",
  "errors": {
    "newPassword": ["Пароль должен быть минимум 6 символов"]
  }
}
```

Семантика статусов:

| Статус | Значение | Реакция фронта |
|---|---|---|
| 400 | невалидные данные формы (`errors`) или неверный старый пароль при смене | показать ошибки у полей |
| 401 | нет/протух токен; неверные логин-пароль на `/login` | стереть токен, на страницу логина (на самой форме логина — «неверный логин или пароль») |
| 403 | пользователь узнан, но прав не хватает | показать «недостаточно прав», на логин не уводить |
| 404 | ресурс не найден | страница/плашка «не найдено» |
| 409 | конфликт данных | показать сообщение, предложить повторить |
| 500 | ошибка сервера | общая плашка ошибки; это баг бэкенда, о нём сообщать |

Важно: `/login` с несуществующим логином и с неверным паролем отвечает
**одинаково** (401, «Неверный логин или пароль.») — это сделано намеренно,
чтобы не раскрывать, какие логины существуют.

## Эндпоинты

| Метод и путь | Токен | Ответ |
|---|---|---|
| `POST /api/users/auth/login` | — | `{"accessToken": "..."}` |
| `GET /api/public/news` | — | страница новостей (только `display=true`, новые сверху) |
| `GET /api/public/teachers` | — | страница карточек преподавателей (по алфавиту фамилий) |
| `GET /api/users/profile` | да | профиль текущего пользователя |
| `POST /api/users/change-password` | да | `200` с пустым телом |
| `POST /api/news` | да, роль админа или модератора | `200` с пустым телом |

Схемы тел — в Swagger. Нюансы, которые оттуда не видны:

* незаполненные поля приходят как `null` (например, `avatar`,
  `previewImage`) — фронт должен это ожидать;
* `createdAt` — ISO-8601 со смещением, например `2026-07-24T10:15:30.123456+04:00`;
* `postType` новости — `news` или `announcements`;
* `POST /api/news` возвращает пустое тело: `id` созданной новости фронту
  не сообщается (известное ограничение, поправится вместе с модулем новостей);
* булевы поля профиля называются `teacher`, `moderator`, `superuser` — без
  префикса `is`.

## Пагинация списков

`GET /api/public/news` и `GET /api/public/teachers` отдают не массив,
а объект-страницу:

```json
{
  "content": [ ... ],
  "page": 0,
  "size": 20,
  "totalElements": 137,
  "totalPages": 7
}
```

`content` — элементы текущей страницы (схема элемента — в Swagger),
`page` — номер страницы, **счёт с нуля**, `totalElements` — сколько элементов
всего с учётом фильтров, `totalPages` — сколько всего страниц при текущем `size`.

Управление — query-параметрами, все необязательны:

| Параметр | По умолчанию | Пример |
|---|---|---|
| `page` | `0` | `?page=2` — третья страница |
| `size` | `20` | `?size=5` |
| `sort` | у каждого эндпоинта свой, см. ниже | `?sort=title,asc` |

Сортировка по умолчанию: новости — по `createdAt` по убыванию (новые сверху);
преподаватели — по фамилии, затем имени по алфавиту. Если запрошенная страница
за пределами данных, приходит `200` с пустым `content` — это не ошибка.
Передача в `sort` несуществующего поля — `500` (известное ограничение,
валидация поля сортировки появится позже); фронту слать только поля из схемы.
