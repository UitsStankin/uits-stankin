#### T-17d Деплой (заблокирован до первого реального деплоя)

Сюда же входит отложенная прод-часть T-09: отдельные прод-секреты в GitHub Actions
Secrets и запись `.env` на сервере из `deploy.yml`.

**Зачем** — после T-17c деплой тянет готовый образ из GHCR, но проверить, что стенд
после этого жив, по-прежнему нечем; `.env` на сервере лежит и обновляется руками,
а прод-секреты не отделены от локальных.

**Готово когда** — прод-секреты в GitHub Actions Secrets, `.env` пишется на сервер
из workflow; после подъёма — smoke-проверка `/actuator/health/readiness` с ретраями,
падение smoke валит деплой; проверено, что VPS тянет приватный пакет из GHCR
(либо пакет переведён в public — образ секретов не содержит).
**Изучить** — GitHub Actions Secrets и environments; чем readiness отличается
от liveness при выкатке; срок жизни `GITHUB_TOKEN` при `docker login` на сервере.
**Опционально, перед публичным запуском** — rate limit на `/login`
(bucket4j или `limit_req` в nginx).

**Долги T-22, всплывающие на этом шаге.** Том `uits_media_data` нужно включить
в бэкап: у базы есть дамп, у загруженных файлов — ничего, и потеря тома означает
битые картинки во всех новостях без возможности восстановления. Раздачу `/media/**`
следует перенести на nginx (ARCHITECTURE §8): сейчас статику отдаёт сам Spring,
занимая на этом потоки приложения. После переноса класс `MediaResourceConfig`
удаляется, а правило `permitAll` в `SecurityConfig` теряет смысл — запросы
за картинками до приложения доходить перестанут.
**Оценка** — выходные, вместе с самим деплоем.

## Параллельно очереди — вертикальный срез

Самый важный непроверенный риск проекта: фронтенд и бэкенд ни разу не разговаривали
друг с другом по-настоящему. Каркас фронтенда собран (роутинг, лейауты, меню, стор,
react-query), но страниц нет, api-клиента нет, а `useAuth` — заглушка: логин выдаёт
`mock-token`, профиль подставляется в коде. Рубеж — «зашёл на сайт, залогинился,
увидел свой профиль и список новостей». Бэкенд для этого готов, доделывать ничего
не нужно.

Зона напарника, но это **критический путь**: пока среза нет, каждый тикет очереди
пишется вслепую. Расхождения мока с реальным контрактом (`email` вместо `username`,
пути со слешем на конце, `isModerator` вместо `moderator`, несуществующий серверный
logout, ожидание массива вместо объекта-страницы) — материал для issue с меткой
`frontend`, а не для переписки в чате.
