# schedule-service

Парсер документов СТАНКИНа: PDF-расписания преподавателя и Excel-ведомости.
Единственный микросервис проекта (обоснование — `docs/ARCHITECTURE.md` §8,
подход — `docs/IMPLEMENTATION.md` §2).

Состояние: T-39 — парсер расписания пар и тесты, T-40 — HTTP-обёртка, образ и запуск
в compose, T-48a и T-48b — парсер расписания экзаменов и ручка к нему, T-66a — разбор
ведомости. Сохранение результата в БД — задача бэкенда (T-41 для расписания, закрыт),
сервис не знает о базе.

## HTTP API

| Метод | Путь | Ответ |
|---|---|---|
| `GET` | `/health` | `200 {"status": "ok"}` |
| `POST` | `/parse` | `200` — расписание пар, контракт ниже; тело запроса — multipart с полем `file` |
| `POST` | `/parse-exams` | `200` — расписание экзаменов, контракт в разделе ниже; тело запроса такое же |
| `POST` | `/parse-gradesheet` | `200` — ведомость (`.xlsx`), контракт в разделе ниже; тело запроса такое же |

Все разбирающие ручки живут по одним правилам: multipart-поле `file`, предел 5 МБ,
ошибки единым телом `{"error": "<код>", "detail": "<сообщение>"}`:

| Код ответа | `error` | Когда |
|---|---|---|
| `400` | `invalid_request` | в запросе нет поля `file` или это не multipart |
| `413` | `file_too_large` | файл больше 5 МБ |
| `422` | `schedule_parse_error` | файл принят, но разобрать не удалось (в том числе больше 50 страниц); `detail` пригоден для показа администратору |
| `500` | `internal_error` | непредвиденная ошибка; подробности только в логах сервиса |

Формат файла проверяется по содержимому (попыткой открыть как PDF или как книгу
Excel), а не по `Content-Type` и не по расширению — их присылает клиент.

Предел размера срабатывает до разбора multipart: middleware отбивает `413`
по заголовку `Content-Length`, а запрос без него (chunked) — счётчиком байтов
по ходу чтения, не буферизуя тело сверх предела на диск. Проверка в самой
ручке остаётся второй линией. Потолок в 50 страниц закрывает PDF-бомбу:
файл на тысячи объявленных страниц влезает в 5 МБ, а `extract_tables`
выполняется на каждой.

Локальный запуск без Docker:

```powershell
.venv\Scripts\python -m uvicorn app.main:app --reload
```

Интерактивная документация — `http://localhost:8000/docs`.

## Использование из Python

```python
from app.parser import parse_schedule
from app.errors import ScheduleParseError

schedule = parse_schedule(pdf_bytes)
```

`parse_schedule` принимает `bytes` или бинарный файловый объект, возвращает
`ParsedSchedule` (pydantic-модель из `app/models.py`). Любой непонятный вход —
не тот файл, чужая таблица, незнакомый тип занятия или формат дат — поднимает
`ScheduleParseError`.

## Контракт результата

```json
{
  "lessons": [
    {
      "week_day": 1,
      "class_time": 1,
      "group": "ИДБ-25-11",
      "name": "Технические средства информационных систем",
      "type": "Лабораторная",
      "subgroup": "Б",
      "cabinet": "216",
      "dates": [
        {"start": "16.03", "end": "27.04", "every_other_week": true}
      ]
    }
  ]
}
```

- `week_day` — день недели 1–6 (понедельник–суббота), в Django-схеме это `week_number`;
- `class_time` — номер пары 1–8;
- `group` — строка; лекция потоку приходит списком групп через запятую, как в PDF;
- `type` — из словаря `LESSON_TYPES` (`Лекция`, `Семинар`, `Лабораторная`);
  новый тип в PDF даст ошибку разбора, словарь дополняется осознанно;
- `subgroup` — буква подгруппы без скобок (`А`/`Б`) или `null`;
- `cabinet` — кабинет как в PDF (`216`, `0804(КК)`, `ИГ-2`) или `null`;
- `dates` — список периодов; `start`/`end` в формате `ДД.ММ` (день и месяц
  проверяются на попадание в календарь), одиночная дата приходит как период
  `start == end`; `every_other_week: true` — занятие через неделю (`ч.н.`),
  `false` — каждую неделю (`к.н.`) и одиночные даты; в Django-схеме это поле
  `alternatively_period`;
- пара, занимающая два слота (слитая ячейка в PDF), приходит двумя элементами
  с одинаковым содержимым и разными `class_time`. Так распознаются только
  ячейки в строке дня: в строках-продолжениях пропуск означает вертикальное
  продолжение ячейки сверху, и горизонтальное слияние там не отличить
  от пустоты;
- `lessons` может быть пустым — это валидный ответ (у преподавателя нет занятий
  в семестре), решение «принять или отклонить» остаётся за бэкендом: с T-46 он
  отвечает `400` и оставляет прежнее расписание нетронутым.

## Формат исходного PDF

Таблица: строка заголовка с временами пар, затем строки дней. Особенности,
на которые опирается разбор:

- название дня в первой колонке записано вертикально, pdfplumber читает его
  задом наперёд — текст переворачивается (`[::-1]`);
- строка с пустой первой колонкой (`None`) — продолжение текущего дня;
- `None` вместо ячейки в строке дня — продолжение слитой ячейки слева
  (пара на два слота);
- в одной ячейке может лежать несколько занятий подряд; каждое заканчивается
  датами в квадратных скобках;
- перенос строки после дефиса (`Объектно-\nориентированное`) склеивается
  без пробела, остальные переносы заменяются пробелом;
- подгруппа — токен строго вида `(А)`; скобки с несколькими заглавными буквами —
  часть номера кабинета (`0804(КК)`, `442(ММ)`), а не подгруппа.

Допущение: на многостраничном PDF каждая страница несёт свою строку заголовка.
Живого многостраничного примера пока не было; тест собирает такой PDF из двух
одностраничных фикстур.

## Разбор расписания экзаменов

Отдельный документ и отдельный парсер: рассылка кафедры с экзаменами и консультациями.
Снаружи — `POST /parse-exams`, из Python вызывается так:

```python
from app.exams import parse_exams
from app.errors import ScheduleParseError

exams = parse_exams(pdf_bytes)
```

Возвращает `ParsedExams`; ошибки — тот же `ScheduleParseError`, что и у расписания пар.

```json
{
  "exams": [
    {
      "date": "2025-05-15",
      "week_day": 4,
      "time_start": "16:00",
      "time_end": "21:10",
      "cabinet": "308",
      "group": "ИДБ-21-11",
      "name": "Применение методов машинного обучения в информационно обоснованных решениях",
      "consultation": {"date": "2025-05-14", "time": "16:00", "cabinet": "308"}
    }
  ]
}
```

- `date` — ISO, потому что год в документе есть (в отличие от расписания пар);
- `week_day` — 1–6, взят из документа и сверен с датой: расхождение считается
  ошибкой разбора, так как означает съехавшую пару строк;
- `time_start`, `time_end`, `consultation.time` — дополнены до `ЧЧ:ММ` (`08:30`),
  в документе часы пишутся без ведущего нуля;
- `cabinet` — как в PDF (`209`, `306(а)`, `0402`); скобка здесь литера аудитории,
  а не подгруппа, разбор подгрупп к экзаменам не применяется;
- `group` — код группы; несколько групп через запятую отдаются одной строкой через
  `, ` (как у расписания пар), каждый код при этом проверяется отдельно;
- `consultation` — может быть `null`: во всех известных файлах консультация есть
  у каждого экзамена, но формат её отсутствие допускает;
- семестра и учебного года внутри файла нет, они выводятся из дат экзаменов;
  год консультации может отличаться от года экзамена (28.12.2024 к 09.01.2025).

### Формат исходного PDF

Одна страница, одна таблица в две колонки, строки идут парами:

```
                          | консультация: 13.05.2025 14:10 ауд. 0402
14.05.2025    | 8:30 - 14:00 ауд. 0402 ИДБ-21-09
Среда         | Системы интеллектуального анализа данных
```

Разбор устроен не так, как у расписания пар, и на то есть причина. `extract_tables()`
молча обрезает содержимое по границе ячейки: длинное название дисциплины физически
вылезает за правую границу таблицы (532.6 при словах до 589.6) и вместо
«…в информационно обоснованных решениях» приходит «…в информационно обоснованны»,
без всякой ошибки.

`page.crop()` эту ловушку не убирает, а переносит: он режет символы по краю бокса
так же молча, а задать бокс шире страницы нельзя. На боевой фикстуре запас до края
листа — 5.4 пункта, меньше одного символа: дисциплина на один символ длиннее уже
теряла бы хвост. Поэтому берётся не кроп, а `page.filter()` — горизонтальная полоса
по вертикальным границам таблицы, слева ограниченная её левым краем, справа
не ограниченная вовсе. Символы, нарисованные за краем листа, при этом сохраняются.
Шапка с фамилией преподавателя лежит выше таблицы и в полосу не попадает.

Обратная сторона решения: раз справа ограничения нет, посторонний текст в правом
поле страницы на высоте строки с дисциплиной (колонтитул, номер страницы, штамп)
приклеится к названию. Ни в одной из трёх рассылок правое поле не занято, а
ограничить полосу справа — значит вернуть обрезку.

Каждая строка обязана совпасть с одним из трёх образцов — консультация, первая строка
экзамена, вторая строка экзамена, — иначе разбор падает. Молча потерять строку нельзя:
непонятная строка всегда ошибка, а не пропуск.

Один преподаватель — один файл. Курсы внутри файла при этом не разделены: в зимней
рассылке Бычковой стоят и ИДБ-21 (выпускной курс), и ИДБ-22, — поэтому считать файл
целиком «выпускным» или «невыпускным» нельзя.

## Разбор ведомости (Excel)

Третий документ и третий парсер: выгрузка ведомости из системы СТАНКИНа — книга
`.xlsx`, по листу на группу. Снаружи — `POST /parse-gradesheet`, из Python:

```python
from app.gradesheets import parse_gradesheets
from app.errors import ScheduleParseError

sheets = parse_gradesheets(xlsx_bytes)
```

Возвращает `ParsedGradeSheets`; ошибки — тот же `ScheduleParseError`.

```json
{
  "sheets": [
    {
      "sheet_name": "ИДБ-25-11",
      "group": "ИДБ-25-11",
      "discipline": "Технические средства информационных систем",
      "department": "УИТС",
      "teachers": ["Чеканин В.А."],
      "semester": "Весенний семестр 2025/2026 учебного года",
      "direction": "09.03.03 «Прикладная информатика»",
      "blocks": ["М1", "М2", "Курсовой проект", "Зачёт"],
      "students": [
        {
          "number": 1,
          "last_name": "Абрамов",
          "first_name": "Александр",
          "patronymic": "Абдул-Керимович",
          "marks": [
            {"block": "М1", "score": 30.0, "text": null, "grade": null,
             "date": null, "teacher": null},
            {"block": "Зачёт", "score": 30.0, "text": null, "grade": "зачтено",
             "date": "2026-06-02", "teacher": "Чеканин В.А."}
          ]
        }
      ],
      "warnings": ["группа в шапке 'ИДБ-25-14' не совпадает с именем листа 'ИДБ-25-15'"]
    }
  ]
}
```

- `blocks` — названия блоков оценок в порядке следования в шапке, как в файле;
  нормализация («М1» → модуль 1, «Зачёт» → форма контроля) — дело бэкенда,
  сервис не знает предметной области;
- `marks` — только те блоки, где у студента есть хоть одно значение; пустой список
  означает «в ведомости по нему ничего нет»;
- `score` и `text` взаимоисключающи: в колонке балла бывает и число, и строка
  (`не допущен`), поэтому число уезжает в `score`, строка — в `text`;
- `date` — ISO; в файле дата бывает как значением ячейки, так и текстом `02.06.2026`;
- `teachers` — список: в шапке бывает несколько преподавателей через запятую.
  Сопоставление с `employee_teacher` — на стороне бэкенда;
- `warnings` — расхождения, которые не мешают разбору, но требуют внимания
  при импорте; список пустой, если всё чисто.

### Формат исходной книги

```
A1  Весенний семестр 2025/2026 учебного года
A2  09.03.03 «Прикладная информатика»
B4  Дисциплина:      C4  Технические средства информационных систем
B5  Группа:          C5  ИДБ-25-11
B7  Преподаватель:   C7  Чеканин В.А.
A9  № п/п | Фамилия | Имя | Отчество | М1 | М2 | Курсовой проект  | Зачёт
A10                                              Балл|Оценка|Дата|Преподаватель
A11 1     | Абрамов | ... | ...       | 30 | 29 |                 | 30 | зачтено | ...
```

Строка заголовка ищется по колонке `Фамилия` в первых 30 строках, метаданные —
по меткам `Дисциплина:`, `Группа:`, `Кафедра:`, `Преподаватель:` выше неё; семестр
и направление меток не имеют и опознаются по содержимому. Отсутствие `Группа:`
или `Дисциплина:` — ошибка разбора.

Схема колонок строится из шапки, а не задаётся в коде: блок — объединённая ячейка
строки заголовка, его подколонки — строка под ней (`Балл`, `Оценка`, `Дата`,
`Преподаватель`); блок без подколонок читается как один балл. Это принципиально:
набор блоков зависит от дисциплины (экзамен вместо зачёта, три модуля вместо двух,
курсовой проект есть не везде), и разбор по фиксированным буквам колонок ломается
на первой же непохожей ведомости — так был устроен парсер старого портала.

Разбор данных:

- студент — строка с непустой фамилией; строки шаблона с номером, но без ФИО
  пропускаются, а строка с ФИО ниже алфавитного конца списка (добавленный позже
  студент) — нет, поэтому обход идёт до конца листа, а не до первой пустой строки;
- `-----` в ячейке означает «нет данных» и даёт `null`, а не ноль;
- отчество бывает пустым — это `warning`, не ошибка;
- `=NOW()` в ячейке «Дата и время» читается как значение из кэша книги, а если
  книгу собрали программно и не открывали в Excel, кэша нет; на разбор это
  не влияет — поле не используется.

Пределы разбора: 60 листов в книге, 5000 строк в листе, 64 МБ распакованного
содержимого архива. Последний потолок закрывает zip-бомбу: книга на миллионы
пустых ячеек влезает в 5 МБ, а `openpyxl` читает её целиком в память.

## Запуск в Docker

Сервис поднимается вместе с базой из `backend/docker-compose.yml`:

```powershell
docker compose up -d schedule-service
```

Порт наружу публикуется только в дев-конфигурации (`SCHEDULE_SERVICE_HOST_PORT`,
по умолчанию 8000) — чтобы бэкенд, запущенный из IDE на хосте, мог до него достучаться.
В прод-контуре сервис остаётся во внутренней сети без публикации портов
(ARCHITECTURE §7); подключение к `docker-compose.prod.yml` и сборка образа в CI —
часть T-17d вместе с остальным прод-контуром.

## Тесты

```powershell
py -3.13 -m venv .venv
.venv\Scripts\pip install -r requirements-dev.txt
.venv\Scripts\python -m pytest
```

`requirements.txt` — то, что уезжает в образ; `requirements-dev.txt` добавляет к нему
инструменты тестов. Фикстуры в `tests/fixtures/` — настоящие рассылки кафедры:
расписания пар (весенний семестр 2026) и расписания экзаменов с префиксом `exams-`
(зима и весна 2025). При смене формата PDF первым делом положить сюда свежий файл
и добиться зелёных тестов.

`gradesheet-idb-25-tsis.xlsx` — ведомость с настоящей структурой, но **обезличенная**:
ФИО студентов заменены на выдуманные, всё остальное сохранено, включая аномалии
исходного файла (несовпадение группы в шапке с именем листа, `-----` вместо оценок,
пустое отчество, строка ниже алфавитного конца списка, `не допущен` в колонке балла).
Ведомости содержат персональные данные — настоящий файл в репозиторий не кладётся,
обезличивать до первого коммита.
